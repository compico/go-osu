> **⚠️ Первый запуск**
>
> Первый запуск программы может занять продолжительное время. В этот момент выполняется расчёт сложности всех beatmap для всех поддерживаемых модов и создаётся локальный кэш. После завершения этой операции последующие запуски будут значительно быстрее.
>
> **Пример производительности:** обработка библиотеки из ~16 000 карт на Intel Core i5-10400F и SSD занимает около **5 минут**.

Настольное приложение для работы с библиотекой [osu!](https://osu.ppy.sh/): парсит `osu!.db` и `.osu`-файлы, поднимает локальный веб-сервер с плеером для прослушивания музыки из бимапов и живёт в системном трее.

Backend написан на Go (Fiber + SQLite), frontend — на Vue 3 + TypeScript + Vite.

## Возможности

- [x] Парсинг `osu!.db` (базы данных клиента osu!)
- [x] Частичный парсинг `.osu`-файлов бимапов
- [x] Веб-плеер для прослушивания музыки из установленных карт
- [x] Иконка в системном трее
- [x] Анализ метрик сложности бимапов (алгоритмы skills, см. ниже)

## Стек

| Компонент       | Технологии                                              |
|-----------------|----------------------------------------------------------|
| Backend         | Go 1.25, Fiber v3, `urfave/cli`, SQLite (modernc, без CGO)|
| Миграции БД     | goose (встроены в бинарь через `embed`, применяются автоматически) |
| Realtime        | Centrifuge (WebSocket, используется в т.ч. для логов браузера) |
| Frontend        | Vue 3, TypeScript, Vite, Pinia, Bootstrap                 |
| Системный трей  | `fyne.io/systray`                                         |

## Структура проекта

```
cmd/                 точка входа и CLI-команды (urfave/cli)
internal/
  config/             загрузка config.yml + CLI-флаги
  database/           подключение к SQLite и применение миграций
  http/               HTTP-сервер (Fiber), обработчики, интеграция с Vite
  logger/             логирование (в т.ч. трансляция в браузер по WebSocket)
  realtime/           WebSocket-сервер (Centrifuge)
  service/            бизнес-логика (чтение osu!.db, каталог карт)
  tray/               иконка в системном трее
  webserver/          вспомогательный веб-сервер
migrations/           SQL-миграции goose, встраиваются через go:embed
pkg/
  osu/                парсинг форматов osu! (database, beatmap, skills)
  vector2d/           2D-векторная математика для алгоритмов skills
frontend/             исходники Vue-приложения (src, public)
assets/               встраиваемые бинарные ассеты (иконка трея)
config.yml            конфигурация приложения
```

> Обратите внимание: `package.json`, `vite.config.ts` и `tsconfig*.json` лежат в **корне репозитория**, а не в `frontend/`. Vite настроен на `root: "frontend"`, но все npm-команды (`npm install`, `npm run dev`, `npm run build`) нужно запускать из корня проекта.

## Требования

- Go 1.25+
- Node.js 20+ и npm
- Установленный osu! (для указания пути к его данным в `config.yml`)

## Установка и запуск (режим разработки)

```bash
git clone https://github.com/compico/go-osu.git
cd go-osu

# зависимости Go подтянутся автоматически при сборке/запуске,
# зависимости фронтенда нужно поставить явно
make deps        # или: npm install
```

Укажите путь к папке osu! в `config.yml`:

```yaml
osu:
  path: "C:/Games/osu!"   # или соответствующий путь в вашей ОС
```

Для разработки нужно запустить **два процесса** параллельно:

```bash
# терминал 1: Vite dev-сервер с hot reload
make frontend-dev

# терминал 2: Go-бэкенд
make run
```

Приложение поднимется на `http://localhost:3000` (порт настраивается в `config.yml`).

Миграции базы данных применяются автоматически при каждом запуске — вручную запускать их не нужно.

## Продакшн-сборка

```bash
make build-prod
```

Эта команда сначала соберёт фронтенд (`npm run build` → `frontend/dist`), а затем скомпилирует бинарь Go. Ассеты фронтенда встраиваются в бинарь на этапе компиляции через `go:embed`, поэтому итоговый бинарь в `bin/` полностью самодостаточен — папку `frontend/dist` доставлять вместе с ним не нужно, как и Node.js/npm на целевой машине. Режим `production`/`development` переключается полем `app.env` в `config.yml`.

## Конфигурация (`config.yml`)

| Секция              | Поле       | Описание                                                              |
|---------------------|------------|------------------------------------------------------------------------|
| `app.env`            | `production` \| `development` | Источник фронтенда: dev-сервер Vite или собранный `dist` |
| `http.port`          | число       | Порт HTTP-сервера (по умолчанию `3000`)                                |
| `database.path`      | путь        | Путь к файлу SQLite (относительно бинаря)                              |
| `log.level`          | `debug`\|`info`\|`warn`\|`error` | Уровень логов, транслируемых в консоль браузера |
| `realtime.port`      | число       | Порт WebSocket-сервера для realtime-функций (по умолчанию `3001`)      |
| `osu.path`           | путь        | Путь к директории установленного osu!                                  |

Путь к конфигу можно переопределить флагом `--config`/`-c` или переменной окружения `APP_CONFIG`.

## Команды Makefile

| Команда               | Что делает                                                             |
|-----------------------|---------------------------------------------------------------------------|
| `make init`           | Скачивает Go-зависимости (`go mod download`)                              |
| `make deps`           | `npm install` для фронтенда                                                |
| `make run`            | Запускает Go-бэкенд в dev-режиме (`go run ./cmd/ http --config config.yml`)|
| `make frontend-dev`   | Запускает Vite dev-сервер с hot reload                                     |
| `make build`          | Собирает debug-бинарь без фронтенда                                        |
| `make build-prod`     | Собирает фронтенд, затем прод-бинарь                                       |
| `make frontend-build` | Только сборка фронтенда (`npm run build`)                                  |
| `make clean`          | Удаляет `bin/` и `frontend/dist/`                                          |

## Skills — анализ сложности бимапов

Пакет `pkg/osu/skills` содержит алгоритмы анализа сложности карт, портированные из проекта [osuSkills](https://github.com/Kert/osuSkills) с разрешения автора ([Kert/osuSkills#5](https://github.com/Kert/osuSkills/issues/5)).

Алгоритмы вычисляют набор метрик по бимапу: Stamina, Tenacity, Agility, Accuracy, Precision, Memory, Reaction и производные от них значения.

Это **порт** с другого языка. Тесты сравнивают результат с оригинальной реализацией на большом наборе карт, и на данный момент значения совпадают практически идеально — оставшиеся расхождения, если они есть, минимальны и связаны с деталями реализации, а не с различиями в методологии. Алгоритмы всё ещё могут дорабатываться по мере обнаружения edge-кейсов.
